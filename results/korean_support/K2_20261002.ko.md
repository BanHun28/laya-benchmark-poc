## 이상 / 주석
- 경고 원문. english 런 5개(K2_scen18-kodesc_en_english, K2_scen18-keydesc_en_english, K2_intent20_en_english, K2_intent20_ko_english, K2_probe-en-v1_english)에서 각 1건: `.venv/lib/python3.12/site-packages/laya/router.py:594: RuntimeWarning: laya: this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10058280825614929 -> 0.5. Treat confidence from the affected entries as uncalibrated.` (다음 줄 `agent = Agent(repo, **kwargs)`). E3 스크립트의 english 로드에서도 1건: `.venv/lib/python3.12/site-packages/laya/agent.py:1869: RuntimeWarning: laya: this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10058280825614929 -> 0.5. Treat confidence from the affected entries as uncalibrated.` 이 경고는 `choice:11+` 버킷의 confidence에만 해당한다(scenario-18, intent-20). 프로브 english 런의 6·3옵션 질문은 해당하지 않는다. upstream `refreshed_clamped` 값도 clamp 후 값이라 비교 조건은 같다. multilingual 런 8개와 빌드·validate·헤드 예산·분석은 경고 0건이다. stderr의 그 밖의 내용은 HF hub `Fetching 5 files: 100%` 진행바뿐이다(캐시 히트). tokenizer 패치 경고, CPU fallback은 없다.
- 재현 sanity: ko scenario 두 런은 P0c 런과 argmax 100/100, answer_confidence 최대 차이 0.0000으로 같다. intent-20 4칸은 upstream과 정확도 Δ 0.000, ECE·mean confidence 차이 ≤ 0.0001이다.
- 지시문의 criteria 변환 `.replace("."," : ")`는 upstream 코드 `.replace(".", ": ")`(bench_local.py:180)와 다르다. MASSIVE 레이블에 `.`이 없어 결과는 같다. 코드를 따랐다.
- MASSIVE ko 첫 100행의 완전 중복 3쌍(P0c 가정 4)은 유지했다. en twin은 모두 서로 다른 문장이다. E3에는 strict와 dup-aware를 함께 적었다(차이는 en→ko P@1 0.31 → 0.32, ko→en P@5 0.43 → 0.44뿐).
- MASSIVE ko는 현지화라 개체가 바뀐 쌍이 있다(예: "임영웅 플레이리스트 재생" ↔ "play a nirvana playlist"). "같은 내용"은 레이블 기준이다.
- 프로브 번역은 LLM으로 한 번에 했다. 역번역·검수는 없다. 원본 프로브의 1인 ad-hoc 라벨과 재사용 금지 헤더를 그대로 물려받는다. tags는 지시대로 `["p0_probe_en"]` 하나만 두었다(원본의 `intent:*` 태그는 없음. expected에 같은 정보가 있다).
- english 참고 런의 헤드 잘림(K2_head_budget.md): scenario 한국어 설명 문항은 cap 9로 100/100행의 18옵션이 모두 잘린다. intent-20은 75/100행이 잘리고 50/100행에서 `iot_hue_light*` 옵션끼리 구분이 사라진다. 프로브 intent는 cap 29로 30/30행이 잘린다. 그러므로 english 런을 "상한"으로 읽을 수 있는 것은 scenario key 렌더링 문항과 프로브 noul뿐이다. multilingual은 모든 문항에서 잘림이 없다.
- 동시 실행: 다른 작업이 같은 디렉터리에 `cards/`, `fetch_cards.sh`, `part2_*`를 쓰고 있었다. 파일 이름이 겹치지 않게 `K2_` 접두어를 썼고 그쪽 파일은 건드리지 않았다. 지표는 정확도·보정뿐이라 CPU 경합의 영향을 받지 않는다(CPU fp32 결정론. ko scenario의 P0c 일치로 확인).
