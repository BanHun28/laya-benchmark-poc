## Anomalies / notes
- Warning text. 1 warning in each of the 5 english runs (K2_scen18-kodesc_en_english, K2_scen18-keydesc_en_english, K2_intent20_en_english, K2_intent20_ko_english, K2_probe-en-v1_english): `.venv/lib/python3.12/site-packages/laya/router.py:594: RuntimeWarning: laya: this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10058280825614929 -> 0.5. Treat confidence from the affected entries as uncalibrated.` (next line `agent = Agent(repo, **kwargs)`). Also 1 in the english load of the E3 script: `.venv/lib/python3.12/site-packages/laya/agent.py:1869: RuntimeWarning: laya: this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10058280825614929 -> 0.5. Treat confidence from the affected entries as uncalibrated.` This warning concerns only the confidence of the `choice:11+` bucket (scenario-18, intent-20). The 6- and 3-option questions of the probe english run are not affected. The upstream `refreshed_clamped` values are also post-clamp values, so the comparison conditions are the same. The 8 multilingual runs and the build, validate, head-budget and analysis steps have 0 warnings. The only other stderr content is the HF hub `Fetching 5 files: 100%` progress bar (cache hit). No tokenizer patch warning, no CPU fallback.
- Reproduction sanity: the two ko scenario runs equal the P0c runs (argmax 100/100, maximum answer_confidence difference 0.0000). The 4 intent-20 cells have accuracy Δ 0.000 against upstream and ECE·mean confidence differences ≤ 0.0001.
- The criteria conversion in the instructions, `.replace("."," : ")`, differs from the upstream code `.replace(".", ": ")` (bench_local.py:180). MASSIVE labels contain no `.`, so the result is the same. The code was followed.
- The 3 exact-duplicate pairs in the first 100 MASSIVE ko rows (P0c assumption 4) were kept. Their en twins are all distinct sentences. For E3, both strict and dup-aware are reported (the only differences are en→ko P@1 0.31 → 0.32 and ko→en P@5 0.43 → 0.44).
- MASSIVE ko is a localization, so some pairs have different entities (e.g., "임영웅 플레이리스트 재생" (play a Lim Young-woong playlist) ↔ "play a nirvana playlist"). "Same content" is defined by the label.
- The probe was translated by an LLM in a single pass. No back-translation or review. It inherits, as they are, the original probe's ad-hoc labels by 1 annotator and its do-not-reuse header. As instructed, tags hold only `["p0_probe_en"]` (no `intent:*` tags from the original; the same information is in expected).
- Head truncation in the english reference runs (K2_head_budget.md): in the scenario Korean-description questions, the cap is 9 and all 18 options are truncated in 100/100 rows. In intent-20, 75/100 rows are truncated, and in 50/100 rows the `iot_hue_light*` options can no longer be told apart. In the probe intent, the cap is 29 and 30/30 rows are truncated. So the english runs can be read as an "upper bound" only for the scenario key-rendering questions and the probe noul. multilingual has no truncation on any question.
- Concurrent execution: another job was writing `cards/`, `fetch_cards.sh` and `part2_*` in the same directory. The `K2_` prefix was used so that file names would not collide, and those files were not touched. The metrics are only accuracy and calibration, so they are not affected by CPU contention (CPU fp32 determinism; confirmed by the ko scenario match with P0c).
- No reruns.
