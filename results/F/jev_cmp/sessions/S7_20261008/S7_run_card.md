## Anomalies / notes

- **No errors.** There were no 5xx · 429 · limit messages, so neither the retry rule (1 retry after 65 s) nor the stop rule was triggered.
- **Input identity (dry runs first).** Before the first request, 4 no-click dry runs were done: the first item of each part (item 1 T9 row 0, item 41 T10 row 0), the longest T9 state (item 29 row 28, 2,117 characters), and a T9 state containing the C1 control character U+0092 (item 21 row 20). In all 4, the form values equaled the input strings without truncation (State maxLength 8,000, option maxLength 80, longest label 73 characters) and sha12 matched. So the session proceeded without any conversion. U+0092 is a character of the original data (it appears to be a mis-decoded Windows-1252 right single quotation mark, to be verified) and is also present, unchanged, in the string Laya reads. It survived the textarea and `JSON.stringify` (the run 21 body byte check matched).
- **T9 option fields.** The T9 `options` in the form file ("false: no, the statement does not hold", "true: yes, the statement holds") are the rendering Laya reads for noul (`render_options`, no criteria). Jev's Boolean has no label · description fields, so the condition is the same as in T5 · T8, where both systems receive only the question sentence.
- **`jev_cmp.py` change (minimal).** `analyze` read Laya reports only from `results/F/jev_cmp/laya/`, so `LAYA_DIRS` (`jev_cmp.py:41-42`), which routes only the T9 · T10 prefixes to `results/T3arm/vanilla/`, and `laya_report()` (`:308-309`) were added, and `laya_cases` (`:313`) and the path display in `request_lines` (`:467`) were made to use them. No files were copied into `laya/`. Regression: the 14 outputs `analyze S1 T2`, `S2 T3`, `S3 T4`, `S3 T5`, `S4 T6`, `S4 T7 en`, `S4 T7 en,de`, `S5 T7 ja · zh-CN · ko`, `S5 T8`, `S4,S5 T7 5 languages`, `stability S1 S1b T2`, `t1 S1,S2` are byte-identical before and after the change, and `S5 T8` also matches S5's `raw/analyze/T8.md`.
- **Instrumentation change (minimal).** `instrument.js` is the same as in S5 except for the version tag (S7) and the session cap (90) (a 3-line diff). The click path of the item scripts is the same as in S5. A read-only block that reads and returns the form DOM state was added for dry runs only (`click: false`) (`s7_prep.py` DRIVER). The session ended at 80 runs, so the cap was not triggered.
- **Host wall clock.** wall − mono offset −1 \~ +1 ms, no steps. `click_epoch_ms` · `click_kst` are values on the monotonic axis, as in S3\~S5.
- **File changes by other processes during the session (not changes made by this session).** `results/F/jev_cmp/__pycache__/s6_summary.cpython-312.pyc` appeared at 15:18:14, and `docs/00_README.md` (15:24:47), `docs/09_laya_vs_jev_plan.md` · `docs/11_three_arm_plan.md` (15:28:07) and `docs/10_paper_laya_vs_jev.md` · `.pdf` (15:37:39 · 15:37:43, the PDF is not included in the public repository) were modified. This session only read `docs/`, and all Python ran with `PYTHONDONTWRITEBYTECODE=1`. The 09 §2 operating rules and §7.3 fields have the same content after the modification.
- **Judgments involving interpretation (to be verified).** The view that, for many of the T10 wrong answers, the gold queue does not match the queue descriptions given to both systems is a judgment made by reading the tickets. Scoring used the dataset labels as they are.
