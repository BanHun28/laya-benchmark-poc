## Anomalies / notes

- **Verbatim warning (server log lines 31-32)**, 1 occurrence at the english slot lazy load:
  ```
  .venv/lib/python3.12/site-packages/laya/router.py:594: RuntimeWarning: laya: this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10058280825614929 -> 0.5. Treat confidence from the affected entries as uncalibrated.
    agent = Agent(repo, **kwargs)
  ```
  The cause is `temperature_by_options["choice:11+"] = 0.1006` in the base english `models/laya/rl_agent_config.json`. It applies only to choices with 11 or more options and does not affect ft-v1 (no `temperature_by_options`) or router_v1 (8 options).
- Check-script warning (tests only): `StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2 instead.`
- Browser console: only the 401s on the first load opened without a key and in the check with the key cleared, and `ERR_CONNECTION_REFUSED` from the 5-second polling after the server was taken down; no JS exceptions. The `favicon.ico` 404 on the first load was removed with `<link rel="icon" href="data:,">`.
- Static file cache: Starlette `StaticFiles` does not send `Cache-Control`, so Chrome once showed a pre-edit `index.html` from its heuristic cache. When checking after UI edits, a hard reload or a `?v=` query is needed (the screenshots were retaken with the final files).
- ft-v1 confidence distribution: the p of the 9 examples cluster at 0.92\~0.96, a margin of 0.017\~0.05 over T 0.907. On the 2,917-row curve too, coverage drops 0.919 → 0.386 between T 0.90 → 0.95. So ROUTE ↔ FALLBACK flips easily when the wording changes slightly or the precision changes (fp16 etc.), and the startup check that T is valid only for this checkpoint and schema must be kept.
- General-mode questions (customer inquiry routing, presets etc.) also use the `multilingual` slot, so ft-v1 answers them (a checkpoint fine-tuned on domain 8). There was no YNAT forgetting (+0.021), but the quality on other question sets was not measured.
- `min_confidence: null` in `/poc/decide` is treated as T (same as omitted). The 05 §3 sketch (`body.get("min_confidence")`) turns abstention reporting off for null, but §5 says "min_confidence=T turns abstention reporting on", so the latter was followed.
- MetricsHook cannot see 503s, because the 503 is raised by the admission in `create_app` before predict.
