The split rule follows the task instructions. For the ko/en paired MASSIVE files (`*_massive_domain_8`, `*_massive_intent_20opt`) and the domain_8 variants with the same row order, a data row with an even index is dev and one with an odd index is test. Here it was asserted that expected and the `scenario:` tag agree for every ko·en row (500/500, 100/100). For the other files, a row is dev if `int(sha256(json.dumps(state, ensure_ascii=False, sort_keys=True)), 16) % 2` is 0 and test if it is 1. For the variant files, the state and expected order were asserted equal to the base, and then only the dev rows were copied (the original header + one `# split: dev ...` line, data lines byte for byte). The same rule is implemented in `row_splits` of `scripts/metrics_extra.py`.

## Anomalies / notes
- Verbatim warning (23 laya-evals runs: all 21 english·typed-decisions runs and the 2 Router runs that loaded english, `router_ko_nsmc_sentiment`, `router_ko_kmhas_type_8`):
  `.venv/lib/python3.12/site-packages/laya/router.py:594: RuntimeWarning: laya: this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10058280825614929 -> 0.5. Treat confidence from the affected entries as uncalibrated.`
  typed-decisions also ships the same `choice:11+=0.10058280825614929` value as english. The multilingual runs have no warning. The per-run list is in summary §10.
- Helper-script warning (B_head_budget.py, not a model run): `[transformers] Ignoring clean_up_tokenization_spaces=True for BPE tokenizer TokenizersBackend. The clean_up_tokenization post-processing step is designed for WordPiece tokenizers and is destructive for BPE (it strips spaces before punctuation). Set clean_up_tokenization_spaces=False to suppress this warning, or set clean_up_tokenization_spaces_for_bpe_even_though_it_will_corrupt_output=True to force cleanup anyway.`
- Shared machine: another job on the same machine (Llama-3.1-8B, CPU about 105%) ran concurrently. Accuracy is unaffected (CPU fp32, deterministic), and the latency column of the reports is not interpreted. Power was AC.
- 3 non-Hangul rows were routed to english by Router auto (NSMC row 140 `wjehdlhs;lhlshlsifhow;`, row 187 `I am the doctor`, K-MHaS type_8 row 181, an English sentence). This is the behavior the rule specifies. That the eval sets contain rows without Hangul is kept as a data-quality note.
- english and typed-decisions truncate the Korean descriptions at 22\~30 tokens per option (`B_head_budget.md`). Their Korean figures and the english "baseline" on `en_massive_domain_8` are values with truncated options.
- The dev/test difference on domain_8 (0.560 vs 0.492) comes from the different scenario composition of the index-parity split. The test half has 1 alarm row (dev 4 rows), 16 calendar rows with 0 correct, and 19 play rows with 5 correct.
- The percentile bootstrap CI of ECE is biased upward, so for a small ECE the point estimate can fall outside the lower bound. Read it only as indicative.
- Doc change observed: the mtime of docs/03, 04, 07 is 16:38 (just before the first run at 16:43). The hashes of the data and the MANIFEST match the 46 reports, so the measurement targets did not change.
- No re-runs. 46/46 exit 0.
