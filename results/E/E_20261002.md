## Anomalies / notes
- **Warning text.** The final run's stderr holds only the `time -p` output (`real 115.07` / `user 187.74` / `sys 67.72`); there are 0 Python·laya·transformers warnings. The two E4 paths (`laya.load(calibration=)`, `apply_calibration_payload`) were wrapped in `warnings.catch_warnings(record=True)` + `simplefilter("always")`, and 0 warnings were caught. No identity warning either.
- **Exploratory run 1 failed (17:28:06, output in a temporary directory).** Text: `RuntimeError: Can't call numpy() on Tensor that requires grad. Use tensor.detach().numpy() instead.` The call path is laya/calibrate.py:286 `logits, _act = agent._forward(batch)` → laya/agent.py:1177 `return logits.float().cpu().numpy(), ...`. Cause: `records_from_labeled` calls the same forward as `predict_batch` (agent.py:1248 `@torch.no_grad()`) but does not turn autograd off. So the output tensor tracks grad and `.numpy()` refuses it. The upstream test (third_party/laya/tests/test_calibrate.py:425-466) uses a stub `_forward` that returns numpy, so it does not exercise the real Agent path. Fix: the call was wrapped in `torch.no_grad()` (scripts/calibrate_ko.py `collect`). This is not a numerical workaround; the caller provides the same execution context that predict_batch provides. Verification: at T = 1, argmax 500/500 against the B reports, max \|Δ answer_confidence\| 0.0001 (batch 16 vs 1). In E4, bit-identical to the API output on 250/250. **Follow-up**: file an upstream issue "records_from_labeled requires no_grad".
- **Exploratory run 2 (17:28:48, temporary directory, payload-fit domain_8).** T, ECE and coverage were the same as in the final run. Its payload (T 2.0245) also passed the E4 check (ECE 0.1228, \|Δ\| 0). The bootstrap CI and the T sweep were added after that.
- **Payload selection rule and G3.** The prior rule was "pooled only if pooled lowers the domain_8 test ECE by more than 0.02". The measurement was 0.123 → 0.098, 0.025 lower. The G3 verdict (≤ 0.10) hinges on this choice (per-task would fail), so the verdict was written as "point estimate passes, borderline·not robust". Dev evidence in the same direction: domain_8 dev ECE per-task 0.078 vs pooled 0.050.
