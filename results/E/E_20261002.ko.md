## 이상 / 주석
- **경고 원문.** 최종 실행 stderr에는 `time -p` 출력(`real 115.07` / `user 187.74` / `sys 67.72`)만 있고 Python·laya·transformers 경고는 0건이다. E4의 두 경로(`laya.load(calibration=)`, `apply_calibration_payload`)는 `warnings.catch_warnings(record=True)` + `simplefilter("always")`로 감쌌는데 잡힌 경고가 0건이다. identity 경고도 없다.
- **탐색 실행 1 실패 (17:28:06, 출력은 임시 디렉터리).** 원문: `RuntimeError: Can't call numpy() on Tensor that requires grad. Use tensor.detach().numpy() instead.` 호출 경로는 laya/calibrate.py:286 `logits, _act = agent._forward(batch)` → laya/agent.py:1177 `return logits.float().cpu().numpy(), ...`이다. 원인: `records_from_labeled`가 `predict_batch`(agent.py:1248 `@torch.no_grad()`)와 같은 forward를 부르는데 autograd를 끄지 않는다. 그래서 출력 텐서가 grad를 추적하고 `.numpy()`가 거부한다. upstream 테스트(third_party/laya/tests/test_calibrate.py:425-466)는 numpy를 돌려주는 stub `_forward`를 써서 실제 Agent 경로를 검증하지 않는다. 조치: 호출을 `torch.no_grad()`로 감쌌다(scripts/calibrate_ko.py `collect`). 이는 수치 우회가 아니라 predict_batch와 같은 실행 컨텍스트를 호출자가 대신 제공한 것이다. 검증: T = 1에서 B 리포트와 argmax 500/500, max \|Δ answer_confidence\| 0.0001(batch 16 vs 1). E4에서 API 출력과 250/250 비트 단위 일치. **후속 추적**: upstream에 "records_from_labeled requires no_grad" 이슈를 낼 것.
- **탐색 실행 2 (17:28:48, 임시 디렉터리, payload-fit domain_8).** 최종 실행과 T·ECE·coverage가 같았다. 그 payload(T 2.0245)도 E4 검증을 통과했다(ECE 0.1228, \|Δ\| 0). bootstrap CI와 T sweep은 그 뒤에 추가했다.
- **payload 선택 규칙과 G3.** 사전 규칙은 "pooled가 domain_8 test ECE를 0.02 넘게 낮출 때만 pooled"였다. 측정치는 0.123 → 0.098로 0.025 낮았다. G3 판정(≤ 0.10)이 이 선택에 걸려 있어서(per-task면 미달) 판정을 "점추정 통과, 경계·비강건"으로 적었다. 같은 방향의 dev 근거: domain_8 dev ECE per-task 0.078 vs pooled 0.050.
- **identity 경고 원문 (stub 검사, 모델 로드 없음).** payload를 `SimpleNamespace(model_id_or_path=<realpath>, subfolder=None, cfg=rl_agent_config.json)`에 `apply_calibration_payload`한 결과: `UserWarning: calibration was fitted for model_id_or_path='models/laya-multilingual' subfolder=None but this agent is model_id_or_path='~/.cache/huggingface/hub/models--convaiinnovations--laya/snapshots/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851/multilingual' subfolder=None. Loading the temperatures anyway.` `'models/laya-multilingual'` 문자열로는 경고가 없다. 검사는 문자열·config 비교(laya/calibrate.py:330-337)이고 가중치 SHA는 보지 않는다.
- **(i)과 (ii)가 같은 이유.** 레코드가 전부 `choice:6-10` 하나에 있어서 type 스칼라 fit과 버킷 fit의 LBFGS 입력이 같다. payload는 type 스칼라 형태다. 이 값은 검증하지 않은 다른 choice 버킷(k=2, 3-5, 11+)에도 걸린다(요약 "결정과 가정").
- **머신 공유.** 같은 머신의 다른 작업(CPU 약 20%, 17:20 기준)이 동시에 돌았다. 확률·정확도는 결정적이고 지연은 측정하지 않았다.
- scripts/calibrate_ko.py는 약 515줄로 지시된 ≈250 \~ 400줄보다 길다. 차이의 대부분은 생성 Markdown 렌더러(약 95줄)다.
- docs 불일치 8건은 요약 §문서 불일치에 file:line으로 적었다. docs와 data/evals는 수정하지 않았다.
- 03 E3의 교차 확인(`laya-evals --min-confidence 0.8`의 abstained 비율, ONNX `--calibration` harness 재검증)은 이번 지시 범위 밖이라 수행하지 않았다.
